The Poisoned Download

A two-minute story about a hacked website, a swapped installer, and the one place the attacker could not reach.

Scroll down
1

Maya needs a calculator for her shop

She downloads Calc 2.4 from the project's own website. She is careful, so she compares the checksum printed beside the button. It matches.

2

03:12. Somebody else visits the website

An attacker takes over the download page. He swaps the installer for one with a little extra inside, and he edits the checksum next to it, in one go.

3

Every check still passes

The next customer is careful too, and the checksum matches, because the website held both the file and the proof. Whoever controls the website controls both.

This has happened to real projects. In 2016 the Linux Mint website and the Transmission website both served poisoned downloads after a break-in.

4

Now the same night, with a seal

When the maintainer shipped 2.4, she sealed the file list in a Bitcoin Cash transaction that only her project's token can make. The attacker can still take the website. He cannot edit the seal.

6

The quieter attack: a swapped release asset

Not every attacker breaks into a website. Some steal a maintainer's login and replace one file on a release that went out weeks ago. Same name, same page, new bytes. The code host even shows the new digest, so anything that trusts the host trusts the swap.

The seal was written when the release shipped, and nobody can edit it afterwards. The old digest on Bitcoin Cash and the new one on the host no longer agree, and that disagreement is the alarm.

7

Check by name, then say thanks

You do not even need the file. Type the release the way you would install it, owner/repo@tag, name==version or name@version, and Release Seal reads the digests GitHub, PyPI or npm publish and holds them against the seal.

When it comes back green, one button sends the maintainer a small BCH tip, straight to the wallet that holds the project. Open source gets checked and gets paid in the same minute.

Try it on mainnet: open the hello-seal demo project with its GitHub release checked by name (emilhuseyn/release-seal@hello-seal-v1.0.0). Maintainers can put the same check on their own download page with one script tag (example).
